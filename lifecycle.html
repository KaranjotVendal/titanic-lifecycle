The Voyage

How one Kaggle project sailed all seven ports of a real machine-learning project — from the first look at the data to a model that watches itself — in six days, with nothing but plain words.

Mon · look & prep Tue · train Wed · judge & pick Thu · ship Fri · watch Sat · tell the world
  1. 1

    Monday · Explore

    Look at the data

    We opened 891 passenger records and just… looked. Ages missing everywhere, and a striking pattern: 74% of women survived, vs 19% of men. Even a silly rule — “all women live” — scores 79%. That became the bar to beat.

    • pandas
    • seaborn
    What happened here
    • Missing-value audit: 20% of ages, 77% of cabins, 2 embarkation ports — gaps we'd later have to fill.
    • Survival by group: survival rates by sex, class, age band and fare — every one a plain “chance of surviving, given this group”.
    • The leak check: made sure no column secretly contains the answer.
  2. 2

    Tuesday morning · Prepare

    Clean & prep

    We turned messy text into tidy numbers: titles pulled out of names (Mr, Mrs, Master), flags for travelling-alone, family size and having-a-cabin, gaps filled with the median, text converted to 1s and 0s.

    • scikit-learn pipelines
    What happened here
    • Feature engineering from Monday's discoveries — every new column exists because a chart suggested it.
    • A reusable prep machine: the same cleaning steps, saved as one object, so test data is treated identically to training data.
    • One honest split: 80% to learn from, 20% held back as the exam — keeping the 38% survival rate in both halves.
  3. 3

    Tuesday afternoon · Train

    Train four candidates

    Same data, four different learners, every run written down in a lab notebook called MLflow. Plot twist: the simplest model won the first round — the fancy ones memorized the answers instead of learning the pattern.

    • 4 algorithms
    • MLflow
    What happened here
    • A straight-line thinker (logistic regression), a flowchart (decision tree), a crowd of flowcharts (random forest), and a crowd that corrects itself (gradient boosting).
    • The deep flowchart scored 99% on practice but 78% on the exam — classic memorizing.
    • MLflow kept every receipt: settings, scores, and the saved model itself.
  4. 4

    Wednesday morning · Judge

    Judge fairly

    One exam is luck; five exams are truth. Re-testing on five different splits flipped the ranking — the self-correcting crowd was best after all (83.6%). And the error table confessed: we miss 3 of every 10 real survivors.

    • cross-validation
    • confusion matrix
    What happened here
    • Five-fold testing: rotate which 20% is the exam, average the five scores — no single lucky split can fool us.
    • Accuracy was hiding things. The error table shows two kinds of wrong: calling a survivor dead (21 people) vs calling a dead person a survivor (12).
    • The simple model stayed as the honest baseline — any winner must beat it properly.
  5. 5

    Wednesday afternoon · Freeze

    Pick & freeze the winner

    We tried 12 combinations of the winner's settings (how many trees, how deep, how bold), picked the best-scoring set, and froze the result as one file — a “champion” that loads anywhere and predicts the same way forever.

    • grid search
    • joblib
    • MLflow
    What happened here
    • Tuning bought only +0.7 point — the week's real wins came from looking and prepping, not knob-twisting. An honest lesson most people miss.
    • The loop closed: the saved file was reloaded in a fresh process and reproduced its score — it's a real artifact, not a pretty file.
  6. 6

    Thursday · Ship

    Serve it like a product

    The notebook became a product: code moved into three small, single-job modules guarded by 18 automated tests, given a phone line (a web API), sealed in a Docker box that runs on any machine, and watched by a robot that re-runs every test on every change.

    • pytest
    • FastAPI
    • Docker
    • GitHub Actions
    What happened here
    • Three jobs: a prep cook (clean data), a cooking class (train), a waiter (answer questions). One file, one job each.
    • Test-driven: tests were written first, and caught real bugs before users could.
    • The proof: one command builds a container; a prediction comes back from inside it — same behavior on any computer.
  7. 7

    Friday · Watch

    Watch & retrain — the loop closes

    A model is a photo of the past; the world moves on. So every batch of new passengers is compared to the training data. When ages and fares drifted, the alarm rang, we retrained, and version 2 was registered next to version 1 — then the voyage starts again.

    • Evidently
    • MLflow registry
    What happened here
    • The smoke alarm, not the fire report: we watch the incoming data because we can't wait for the answers — those arrive too late.
    • Statistical tripwires compare each column's old vs new shape and ring when the difference is too big to be luck.
    • End-to-end, for real: drift planted → alarm fired → retrain ran → MLflow showed v1 and v2 side by side.

Port 8 — tell the world

Saturday: the prediction file was validated and submitted to Kaggle for a real leaderboard score, and the whole voyage was written up in a README with a one-page math cheat sheet. The model that keeps watching itself never really finishes sailing. ↻

One project, six days, seven ports — research → experimentation → selection → production → deployment → monitoring → retraining.
