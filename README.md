# Titanic — Full ML Lifecycle

A Kaggle Titanic project built as a **portfolio piece demonstrating the entire machine-learning lifecycle** — research → experimentation → selection → production → deployment → monitoring → retraining.

New here? Open **[`lifecycle.html`](lifecycle.html)** — the whole project as a one-page visual voyage.

## The lifecycle, as commits

| Stage | What happened | Where |
|---|---|---|
| 🔍 Explore | EDA: missing values, distributions, survival patterns, leakage screen | `notebooks/01_eda.ipynb` |
| 🧹 Prepare | Feature engineering + preprocessing pipeline (imputation, one-hot) | `notebooks/02_features_and_models.ipynb` |
| 🏋️ Train | 4 algorithms, every run tracked in MLflow | `notebooks/02_features_and_models.ipynb` + MLflow |
| ⚖️ Judge | 5-fold cross-validation, confusion matrix, dumb-rule baseline | `notebooks/03_model_selection.ipynb` |
| 🏆 Freeze | GridSearchCV tuning, champion artifact saved & reload-verified | `notebooks/03_model_selection.ipynb`, `models/` |
| 🚀 Serve | Package refactor (TDD), FastAPI, Docker, CI | `src/titanic/`, `tests/`, `Dockerfile`, `.github/workflows/` |
| 👁️ Watch | Drift detection (Evidently) + retraining loop (MLflow registry v1→v2) | `notebooks/04_drift_report.ipynb`, `src/titanic/monitor.py`, `src/titanic/retrain.py` |
| 📦 Submit | Format-validated Kaggle submission file generator | `src/titanic/make_submission.py` |

## Results (5-fold cross-validation, identical footing)

| model | CV accuracy |
|---|---|
| **gradient boosting (tuned)** — champion | **83.0%** |
| gradient boosting (default) | 82.3% |
| logistic regression | 81.6% |
| dumb rule ("all women survive") | 77.7% |

Tuning bought +0.7pt — the week's wins came from EDA-driven feature engineering, not knob-twisting. The champion's error profile (confusion matrix, `03_model_selection.ipynb`): survived-class recall 0.70 — it misses 3 of 10 real survivors.

## Quick start

```bash
# 1. environment
uv sync

# 2. prove the tests pass (26 of them)
uv run pytest -q

# 3. retrain the champion from raw data
uv run python -m titanic.train

# 4. run the API
uv run uvicorn titanic.serve:app --reload
#    POST /predict  {"Pclass": 1, "Name": "...", "Sex": "female", "Age": 38, "SibSp": 1, "Parch": 0, "Fare": 71.28, "Embarked": "C"}

# 5. or ship it in a container
docker build -t titanic . && docker run -p 8000:8000 titanic

# 6. browse the experiments
uv run mlflow ui --backend-store-uri sqlite:///mlflow.db

# 7. run the monitoring -> retraining loop
uv run python -m titanic.monitor data/raw/train.csv data/processed/drifted.csv   # exit 1 = drift
uv run python -m titanic.retrain data/raw/train.csv                              # registers a new model version

# 8. generate a Kaggle submission file (validated before it can be written)
uv run python -m titanic.make_submission
```

## Notes

- Raw Kaggle data is not committed (gitignored); download `train.csv`/`test.csv` from the [competition page](https://www.kaggle.com/competitions/titanic/data) into `data/raw/`.
- The test suite trains tiny synthetic models — it runs anywhere, including CI, with no data or artifacts present.
- The drift report notebook (`04`) regenerates `data/processed/drifted.csv`; both are gitignored as regenerable.
